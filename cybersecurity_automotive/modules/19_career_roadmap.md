## 19.3 Certification Path

```
BEGINNER → INTERMEDIATE → ADVANCED CERTIFICATIONS:

BEGINNER (Start here):
  □ CompTIA Security+ 
    Why: Foundation of cybersecurity, widely recognized
    Cost: ~$400  |  Prep: 3 months
    
  □ SANS SEC401 (Security Essentials)
    Why: Comprehensive, vendor-neutral
    Cost: ~$5000 (with GIAC GSEC exam)

AUTOMOTIVE-SPECIFIC (High Value):
  □ No current dedicated automotive CS cert (gap in market)
  
  → Instead: combination approach:
    1. ISO 21434 Foundation course (TÜV SÜD, DEKRA training)
       Why: Understand the standard you'll be audited against
       Cost: ~$1000–$3000
    
    2. Vector or Vector Academy AUTOSAR training
       Why: AUTOSAR is the implementation standard
       
    3. UNECE R155 Implementation Workshop
       Why: Regulatory compliance training

PENTEST FOCUSED:
  □ OSCP (Offensive Security Certified Professional)
    Why: Hands-on, respected, practical exploitation skills
    Cost: ~$1500  |  Prep: 6-12 months
    
  □ GPEN / GWAPT (GIAC)
    Why: Broad pentest / web application pentest
    
  □ CRTSA (Certified Road Transport Security Assessor) — emerging cert
    Offered by: European automotive security organizations

EMBEDDED / HARDWARE:
  □ CHES (Cryptographic Hardware and Embedded Systems) — academic
  □ CEH (Certified Ethical Hacker) — basic, not deep enough for auto
  
MANAGEMENT / ARCHITECT:
  □ CISSP (Certified Information Systems Security Professional)
    Why: Broad security management, recognized by CISOs
    Cost: ~$700  |  Requires: 5 years experience
    
  □ ISO/IEC 27001 Lead Implementer
    Why: Security management system (complements R155 CSMS)

CODING:
  □ CSSLP (Certified Secure Software Lifecycle Professional)
    Why: Secure development lifecycle, maps well to ASPICE
```

## 19.5 Portfolio Projects

```
PROJECT 1: CAN IDS (Intrusion Detection System)
  What to build:
    - Python: real-time CAN monitor with rule engine
    - Rules: ID whitelist, DLC validation, cycle time check, counter verification
    - Dashboard: web UI showing alerts + statistics
  Skills demonstrated: python-can, automotive protocol knowledge, security design
  Time: 2-3 weeks
  GitHub: publish with README + demo GIF

PROJECT 2: UDS Security Tester Tool
  What to build:
    - Python CLI tool for automated UDS security testing
    - Tests: lockout policy, seed entropy test, session boundary test
    - Report: HTML/PDF output with CVSS scoring
  Skills demonstrated: udsoncan, security testing methodology, tool development
  Time: 3-4 weeks

PROJECT 3: SecOC Simulation
  What to build:
    - Simulate sender + receiver with SecOC (from scratch, no AUTOSAR)
    - Implement freshness counter, CMAC verification, attack scenarios
    - Demo: show replay attack detection, tampering detection
  Skills demonstrated: cryptography (CMAC), CAN protocol, AUTOSAR concepts
  Time: 1-2 weeks

PROJECT 4: Firmware Analysis Script Collection
  What to build:
    - Entropy analyzer (binwalk-like, from scratch in Python)
    - String extractor with security-relevant pattern matching
    - YARA rule scanner for automotive firmware
  Skills demonstrated: binary analysis, Python, security research
  Time: 2 weeks

PROJECT 5: TARA Document (on public vehicle)
  What to create:
    - Perform TARA on a publicly available/open-source vehicle project
    - Use the templates in this repository
    - Document 5-10 threats with full ISO 21434 format
  Skills demonstrated: risk analysis, ISO 21434, analytical thinking
  Time: 2 weeks
```

## 19.8 30-60-90 Day Plan (New Cybersecurity Engineer Role)

```
FIRST 30 DAYS — UNDERSTAND:
  [ ] Meet all team members: safety, software, system, quality, management
  [ ] Get access to: AUTOSAR configurator, CANoe/CAPL, JIRA, Git
  [ ] Read: current TARA documents for vehicle programs
  [ ] Understand: which ECUs are in scope, which have cybersecurity goals
  [ ] Review: existing test bench setup (hardware, software versions)
  [ ] Shadow: pentest activities or test case reviews
  [ ] Read: OEM-specific cybersecurity guidelines / internal standards

DAYS 31–60 — CONTRIBUTE:
  [ ] Review 2-3 TARA documents and provide comments
  [ ] Write 5-10 UDS security test cases in CAPL or Python
  [ ] Execute existing security test suite on test bench
  [ ] Identify 1 gap in current security test coverage
  [ ] Attend and contribute to security architecture review meeting

DAYS 61–90 — LEAD:
  [ ] Own 1 complete security test module (e.g., all SecOC tests)
  [ ] Write threat model for 1 interface (e.g., OBD-II security)
  [ ] Present findings at team meeting
  [ ] Propose 1 security improvement (process or technical)
  [ ] Start mentoring junior engineer on 1 topic
```

```
KEY TAKEAWAYS:
```
