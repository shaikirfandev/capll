# Part 24 — Interview Preparation

---

## 24.1 Beginner Questions (Q1–Q25)

**Q1. What is an ECU?**
An ECU (Electronic Control Unit) is a dedicated embedded computer in a vehicle that controls a specific function (e.g., engine, brakes, airbag). It contains a microcontroller, flash memory, RAM, and communication interfaces (CAN, LIN, Ethernet).

**Q2. What is CAN bus?**
CAN (Controller Area Network, ISO 11898) is a broadcast serial protocol for automotive ECU communication. Messages are identified by priority-based IDs; the lower the ID, the higher the priority. Speed up to 1 Mbps, up to 8 bytes payload.

**Q3. What is CAN FD?**
CAN FD (Flexible Data Rate) extends Classical CAN with up to 64 bytes payload and up to 8 Mbps data phase bit rate, while keeping the 11/29-bit arbitration.

**Q4. What is LIN bus?**
LIN (Local Interconnect Network) is a low-cost single-wire serial protocol at up to 20 kbps, using master/slave architecture. Used for simple sensors and actuators (mirrors, seat motors).

**Q5. What is AUTOSAR?**
AUTOSAR (AUTomotive Open System ARchitecture) is a standardized software architecture for automotive ECUs. Classic AUTOSAR targets MCUs with static configuration; Adaptive AUTOSAR targets SoCs with dynamic service-oriented communication.

**Q6. What is the AUTOSAR BSW?**
BSW (Basic Software) is the middleware layer in Classic AUTOSAR containing communication (COM, PduR, CanIf), diagnostics (Dcm, Dem), memory (NvM), and OS modules. It is configured via ECUC files and the code is generated by tools like DaVinci Configurator.

**Q7. What is UDS?**
UDS (Unified Diagnostic Services, ISO 14229) is the standard protocol for communicating with vehicle ECUs for diagnostics, calibration, and flashing. Common services: 0x22 ReadDataByIdentifier, 0x14 ClearDTCs, 0x19 ReadDTCs, 0x27 SecurityAccess, 0x34 RequestDownload.

**Q8. What is a DTC?**
A DTC (Diagnostic Trouble Code) is a fault code stored in ECU memory when a fault is detected. Example: P0101 (Mass Air Flow Sensor). DTCs are read with UDS service 0x19 and cleared with 0x14.

**Q9. What is DoIP?**
DoIP (Diagnostics over Internet Protocol, ISO 13400) enables UDS diagnostics over Ethernet/TCP. Default port: 13400. Used in modern vehicles with Ethernet backbone.

**Q10. What is SOME/IP?**
SOME/IP (Scalable service-Oriented MiddlewarE over IP) is the middleware protocol for service-oriented communication over Automotive Ethernet. Supports methods, events, and fields. Paired with SOME/IP-SD for service discovery.

**Q11. What is a DBC file?**
A DBC (Database CAN) file defines all CAN messages and signals: message IDs, signal names, bit positions, byte order, scaling, and unit. Used by CANoe and other tools for symbolic signal display.

**Q12. What is a bootloader?**
A bootloader is the first code to execute on MCU startup. It initializes hardware and jumps to the application. It also enables firmware flashing via CAN/Ethernet using UDS programming session.

**Q13. What is HIL testing?**
HIL (Hardware-in-the-Loop) testing connects a real ECU to a simulator that emulates the rest of the vehicle (sensors, actuators, other ECUs). Used for automated and safety testing without a full vehicle.

**Q14. What is ASIL?**
ASIL (Automotive Safety Integrity Level) is the safety requirement level defined by ISO 26262: QM (no safety requirement), ASIL-A (lowest), ASIL-B, ASIL-C, ASIL-D (highest). ASIL-D applies to systems like AEB braking.

**Q15. What is the RTE in AUTOSAR?**
RTE (Run-Time Environment) is the generated middleware layer in Classic AUTOSAR that connects SWCs (Software Components) to BSW modules. The RTE provides APIs like `Rte_Write_*`, `Rte_Read_*`, `Rte_Call_*`.

**Q16. What is a SWC in AUTOSAR?**
SWC (Software Component) is the building block of AUTOSAR application layer. SWCs communicate via ports and interfaces through the RTE. They are described in ARXML files.

**Q17. What is Yocto?**
Yocto is a build system for creating custom embedded Linux images. Used for IVI, cluster, and ADAS domain controllers running Linux (e.g., built with Yocto for Renesas R-Car or NXP i.MX8).

**Q18. What is MISRA C?**
MISRA C is a set of coding guidelines for C programming in safety-critical automotive software. It restricts dangerous C constructs (pointer arithmetic, dynamic memory allocation, etc.). Compliance checked by static analysis tools like Polyspace or cppcheck.

**Q19. What is ARXML?**
ARXML is the XML-based configuration file format for AUTOSAR. It describes SWC definitions, port interfaces, BSW module configuration, and communication matrices.

**Q20. What is a calibration file?**
A calibration file (e.g., .a2l, .dat, .hex) contains parameter values that tune ECU behavior (lookup tables, thresholds, PID gains) without changing code. Read and written by calibration tools like CANape/INCA.

**Q21. What is CAPL?**
CAPL (Communication Access Programming Language) is a C-like scripting language used in Vector CANoe for simulating ECUs, writing test cases, and automating diagnostic sequences.

**Q22. What is python-can?**
python-can is a Python library for sending and receiving CAN messages using SocketCAN, PCAN, Vector, or virtual CAN interfaces. Used for test automation.

**Q23. What is E2E protection?**
E2E (End-to-End) protection is an AUTOSAR library that adds a CRC and counter to safety-critical CAN messages to detect transmission errors, message loss, and out-of-order delivery.

**Q24. What is a watchdog in an ECU?**
A watchdog timer is a hardware/software mechanism that resets the ECU if the application stops "kicking" (resetting) it within a defined interval — indicating the software has crashed or hung.

**Q25. What is GNSS?**
GNSS (Global Navigation Satellite System) includes GPS, GLONASS, Galileo, and BeiDou. In automotive, a GNSS module provides vehicle position, speed, and heading. Used in TCU for vehicle tracking and ADAS for localization.

## 24.2 Intermediate Questions (Q26–Q60)

**Q26. Explain the difference between Intel and Motorola byte order in CAN signals.**
- **Intel (little-endian):** Least significant byte at lowest address; LSB is start bit. More common.
- **Motorola (big-endian):** Most significant byte at lowest address; MSB is start bit.
A mismatch between DBC definition and ECU configuration causes signals to show completely wrong values.

**Q27. What is PduR in AUTOSAR and what does it do?**
PduR (PDU Router) routes PDUs (Protocol Data Units) between BSW modules. It acts as a switch connecting COM to CanIf, CanTp, SOME/IP stack, and other transport modules. Configured via routing tables in ECUC.

**Q28. How does CAN arbitration work?**
When two nodes transmit simultaneously, bits are compared. A dominant (0) bit overrides a recessive (1) bit. The node transmitting a recessive bit while seeing a dominant bit loses arbitration and stops transmitting. The node with the lowest ID (most dominant bits) wins.

**Q29. What is SOME/IP-SD used for?**
SOME/IP-SD (Service Discovery) enables dynamic discovery of services at runtime. A server sends OfferService; clients respond with FindService or SubscribeEventgroup. Without SD, all endpoints must be statically configured.

**Q30. What is the difference between a pending DTC and a confirmed DTC?**
- **Pending DTC:** Fault detected in current drive cycle but not yet confirmed (debounce counter not reached)
- **Confirmed DTC:** Fault confirmed after required number of occurrences; stored persistently; may activate MIL (Malfunction Indicator Lamp)

**Q31. What is OTA and what are the types?**
OTA (Over-The-Air) is remote software update via cellular network. FOTA (Firmware OTA) updates ECU firmware; SOTA (Software OTA) updates application-level software, maps, calibration data. A/B partitions enable safe updates with rollback capability.

**Q32. What is an integration baseline?**
A fixed, tested, and documented set of software versions for all ECUs that form a known-good baseline for testing. Changes are only introduced at new baseline boundaries, ensuring traceability.

**Q33. What is ISO 26262 and why does it matter for integration engineers?**
ISO 26262 is the functional safety standard for road vehicles. Integration engineers must: verify safety mechanisms, run fault injection tests, document traceability from safety requirements to test cases, and sign off on safety work products for each integration phase.

**Q34. Explain the UDS security access mechanism.**
Security Access (0x27) uses seed/key challenge-response:
1. Tester sends 0x27 0x01 (request seed)
2. ECU responds with a random seed
3. Tester computes key = f(seed, secret)
4. Tester sends 0x27 0x02 + key
5. ECU verifies; if correct, unlocks session

**Q35. What is the difference between SIL, MIL, and HIL?**
- **MIL (Model-in-the-Loop):** Testing control algorithm model in Simulink
- **SIL (Software-in-the-Loop):** Testing compiled code on PC with simulated environment
- **HIL (Hardware-in-the-Loop):** Testing real ECU hardware with simulated vehicle environment

**Q36. How do you debug a watchdog reset?**
1. Check DTC: WdgM DTC usually indicates which supervised task timed out
2. Use Trace32: set breakpoint before WdgM_MainFunction; profile task execution times
3. Find the overrunning task; measure with WCET analysis
4. Optimize or move heavy processing to lower-priority task

**Q37. What is the purpose of the Dem module in AUTOSAR?**
DEM (Diagnostic Event Manager) manages DTCs: stores DTC events in NvM, manages DTC status bytes, handles debounce, controls MIL indicator requests, and responds to UDS ReadDTCInformation requests via DCM.

**Q38. What is TSN in Automotive Ethernet?**
TSN (Time-Sensitive Networking) adds determinism to standard Ethernet:
- IEEE 802.1AS: Time sync (gPTP)
- IEEE 802.1Qbv: Scheduled traffic
Used in ADAS for sensor timestamp alignment and in gateway for real-time signal routing.

**Q39. What is an A2L file?**
An ASAP2 (A2L) file describes ECU internal variables (measurements and calibration parameters): memory addresses, data types, conversion formulas. Used by CANape/INCA to read/write ECU variables without changing firmware.

**Q40. What is CanSM in AUTOSAR?**
CanSM (CAN State Machine) manages the CAN bus state for each CAN network: offline, silent, full communication. It handles bus-off recovery automatically (restart after bus-off detection).

**Q41. How do you verify that a CAN signal is being transmitted correctly?**
1. Load DBC in CANoe → start measurement
2. Observe signal in signal monitor: check value, period, encoded value
3. Compare raw hex bytes against manual calculation using DBC definition
4. Verify endianness (Intel vs Motorola)

**Q42. What is ASPICE?**
Automotive SPICE (Software Process Improvement and Capability dEtermination) is a process assessment model. OEMs require Tier-1 suppliers to achieve CL2 or CL3. SWE.5 (Software Integration and Integration Test) directly covers integration activities.

**Q43. What is the purpose of the NvM module in AUTOSAR?**
NvM (Non-volatile Memory Manager) provides a NVRAM abstraction for storing persistent data (odometer value, calibration, DTC status, adaptations). Data is organized in blocks; each block can be read/written with `NvM_ReadBlock()` / `NvM_WriteBlock()`.

**Q44. What is SecOC in AUTOSAR?**
SecOC (Secure Onboard Communication) adds a Message Authentication Code (MAC) to CAN/Ethernet PDUs using cryptographic keys from the HSM. It protects against CAN message injection attacks.

**Q45. What is the difference between fail-safe and fail-operational?**
- **Fail-safe:** System enters a safe (often inactive) state upon fault (e.g., AEB disabled if sensor fails)
- **Fail-operational:** System continues to operate at reduced capability upon fault (e.g., ADAS falls back to radar-only when camera fails)

## 24.3 Advanced Questions (Q46–Q80)

**Q46. Explain the complete UDS flashing sequence.**
Programming session → Security access (seed/key) → WriteDataByIdentifier (fingerprint) → RoutineControl Erase → RequestDownload (address, size) → loop TransferData → RequestTransferExit → RoutineControl CheckDependencies → ECUReset

**Q47. How does SOME/IP-SD service discovery work in detail?**
Server boots → calls `offer_service` → vsomeip/ara::com sends UDP multicast OfferService to 224.0.0.1:30490. Client calls `find_service` → FindService broadcast. Server responds. Client sends SubscribeEventgroup → Server responds SubscribeAck. Events flow unicast from server to subscriber.

**Q48. Explain E2E profile 2 (common in AUTOSAR).**
E2E Profile 2 appends to the PDU: 1-byte CRC (CRC8 over data + Data ID), 1-byte Counter (0–15 wrapping), 2-byte Data ID. Receiver checks CRC match, counter increment, and Data ID. Errors detected: bit errors, repetition, loss, insertion.

**Q49. What is the difference between Adaptive and Classic AUTOSAR communication?**
Classic: Static COM/PduR/CanIf configuration at compile time; signals known at build time; no dynamic discovery. Adaptive: ara::com with SOME/IP-SD; services discovered at runtime; binding can be SOME/IP, local IPC, or DDS; dynamic deployment.

**Q50. How does dual-bank OTA flashing work?**
Two flash partitions (A and B) are maintained. Update writes to inactive bank while active bank runs. After write+verification, bootloader switches boot bank. On first boot from new bank, validation runs. If validation fails, bootloader reverts to previous bank (rollback). This prevents brick scenarios.

**Q51. Explain gPTP (IEEE 802.1AS) in automotive context.**
gPTP provides nanosecond-accurate clock synchronization over Automotive Ethernet. A GNSS receiver acts as Grandmaster; all ECUs on the network synchronize their local clocks. Used in ADAS to timestamp sensor data from all sensors to a common time base for accurate fusion.

**Q52. What is the purpose of CanTp (ISO 15765-2)?**
CAN Transport Protocol enables sending messages larger than 8 bytes over CAN. Uses segmentation: First Frame (FF) for start, Consecutive Frames (CF) for continuation, Flow Control (FC) for pacing. Used by UDS for large diagnostic responses and firmware download.

**Q53. How do you handle a supplier ECU that delivers wrong signals?**
1. Capture CAN trace in CANoe with DBC
2. Compare signal values against ICD/DBC specification
3. Document specific signals that are wrong (ID, byte position, value)
4. Raise defect in joint tracker with captured log evidence
5. Coordinate with supplier to confirm root cause
6. Verify fix in next delivery

**Q54. What is WCET and why does it matter?**
WCET (Worst Case Execution Time) is the maximum time a task/function can take in any scenario. In AUTOSAR, each runnable has a WCET budget. If WCET exceeds the task period, task overrun and watchdog reset occur. Measured with Trace32 ETM trace or instrumented timing measurements.

**Q55. Explain the DoIP vehicle announcement and routing activation.**
On startup, DoIP entity broadcasts UDP Vehicle Announcement (type 0x0004) with VIN, EID, GID. Tester sends RoutingActivationRequest (TCP). DoIP entity registers client and responds RoutingActivationResponse. After activation, UDS messages can be routed.

**Q56. How do you ensure integration test completeness?**
Requirements traceability matrix (RTM): every integration requirement linked to at least one test case. Test coverage metric: (tested requirements) / (total requirements) × 100%. Target ≥ 100% for ASIL-B/C/D. Reviewed in integration review meeting before release.

**Q57. What is the FiM module in AUTOSAR?**
FiM (Function Inhibition Manager) disables application functions when specific DTCs are active. For example, if DTC for radar failure is active, FiM inhibits ACC feature. Configured with InhibitionMask linking DEM events to functional identifiers.

**Q58. How does an integration engineer manage interface changes during the project?**
Interface Control Document (ICD) is baselined and change-controlled. All changes go through ICR (Interface Change Request): impact analysis, approval by all affected ECU owners, updated DBC/ARXML, re-integration and re-test of affected ECUs. Changes tracked in DOORS/Polarion.

**Q59. What is the BswM module?**
BswM (BSW Mode Manager) implements the BSW behavior based on mode conditions. It configures which BSW modules are active in each ECU mode (e.g., sleep mode: disable COM; running mode: enable full communication). Rules configured in ECUC BswM module.

**Q60. Explain Adaptive AUTOSAR process lifecycle.**
Each Adaptive Application (AA) is a POSIX process. Execution Manager (EM) reads manifests → starts AAs based on Machine State and Function Group state. AAs call `ReportApplicationState(kRunning)` when ready. EM monitors; restarts on crash per restart policy. State transitions: Off → Init → Running → Shutdown.

## 24.4 Senior/Lead Questions (Q61–Q100)

**Q61. How do you prioritize defects for a release?**
P0/P1 (blocking safety/critical function) must be fixed before release. P2 (major, workaround possible) reviewed with PM — fix or accept with documented risk. P3/P4 (minor/cosmetic) accepted for post-release. Decision documented in release notes.

**Q62. How do you manage integration when multiple suppliers are developing ECUs in parallel?**
1. Define and baseline all interfaces early (ICD, DBC, ARXML)
2. Provide integration stubs for missing ECUs in CANoe
3. Define supplier delivery milestones with entry/exit criteria
4. Run incoming integration test on every delivery
5. Joint weekly integration status meeting
6. Escalate blockers immediately

**Q63. Describe your approach to root cause analysis for a hard-to-reproduce defect.**
1. Maximize observability: enable extended logging, add Trace32 trace
2. Try to narrow conditions: temperature, time, specific signal sequence
3. Analyze all available logs and traces
4. Review code for timing-sensitive paths, race conditions
5. If needed: inject same conditions artificially to reproduce
6. Once found: document with 5-Why analysis

**Q64. How do you manage OTA risk for a large fleet rollout?**
Staged rollout: 0.1% → 1% → 10% → 100%. Define automatic pause if success rate drops below threshold (e.g., 97%). Monitor: DTC trends, crash reports, cellular connection time. Have rollback plan ready. Test OTA on internal fleet for 2 weeks before public rollout.

**Q65. What metrics do you track as integration lead?**
HIL test pass rate, build success rate, P1/P2 defect count, mean time to resolve, integration baseline on-schedule %, flash success rate, regression rate (defects re-opened), requirements coverage %, ECU delivery on schedule.

**Q66. How do you handle a safety-critical defect found during vehicle integration 1 week before release?**
1. Immediately assess severity and ASIL level
2. P1 if safety-critical; escalate to project manager and safety manager
3. Freeze release until root cause confirmed
4. Assign best available engineer to root cause analysis
5. Fix, regression test, safety review
6. If fix cannot be done in time: assess if workaround (deactivate feature) is acceptable
7. Document risk acceptance with management and safety manager sign-off

**Q67. What is an integration entry/exit criteria and why are they important?**
Entry criteria: preconditions that must be met before starting a phase (e.g., "unit tests passed" before ECU integration). Exit criteria: conditions that must be met to complete a phase (e.g., "no P1 open, HIL pass rate ≥ 98%"). They prevent skipping phases under schedule pressure and ensure quality gates.

**Q68. How do you handle CAN bus load optimization?**
1. Measure bus load in CANoe under normal conditions (target: < 50% average, < 70% peak)
2. Identify high-frequency messages that can be reduced (e.g., 1ms → 5ms for non-safety signals)
3. Compress multiple signals into fewer messages
4. Move less time-critical signals to lower-speed CAN bus
5. Migrate bandwidth-hungry data to CAN FD or Ethernet

**Q69. Explain your approach to integration test automation.**
Write reusable test libraries in Python (python-can) or CAPL. Tests read expected values from test specification (CSV/JSON). CI pipeline runs automated tests on every build. Test report auto-generated and linked to Jira. Regression suite run nightly on HIL. New features require test coverage before merge.

**Q70. What is your strategy for managing an integration milestone delay?**
1. Assess delay root cause: supplier late delivery, defect not fixed, ECU hardware issue
2. Identify critical path: which activity is blocking downstream?
3. Parallelize: can other integration work continue with stubs?
4. Escalate: communicate to PM with impact assessment and mitigation options
5. Resource: add engineer to blocked item if addressable by more effort
6. Update plan: revise schedule with realistic dates; communicate to all stakeholders

## 24.5 Architecture Questions (Q71–Q100 summary)

**Q71. What are the key differences between domain, zone, and central compute architectures?**
- **Domain architecture:** ECUs organized by function domain (ADAS, body, powertrain); domain controller per domain
- **Zone architecture:** ECUs organized by physical zone (front, rear, left, right); zone controller connects local sensors/actuators; central compute handles logic
- **Central compute:** Most logic in one powerful computer; ECUs become I/O nodes

**Q72. When would you choose Classic vs Adaptive AUTOSAR?**
Classic: resource-constrained MCU, hard real-time, safety-critical, static topology (powertrain, brakes, body). Adaptive: SoC-based, Linux/QNX, dynamic services, OTA updates, ML inference, ADAS domain controller, IVI.

**Q73. How do you design a robust OTA update architecture for safety-critical ECUs?**
Dual-bank flash for all ECUs, digital signatures (ECDSA-P256), TLS 1.3 for download, mutual TLS between TCU and server, anti-rollback counter in OTP, staged rollout with auto-pause, pre-condition checks before installation, post-install validation, rollback on failure.

**Q74. How do you architect sensor fusion for a multi-sensor ADAS system?**
Central fusion on ADAS domain controller: each sensor has driver → object detection → coordinate transform to vehicle frame → fusion algorithm (EKF or MHT) → object list with confidence. gPTP timestamps all inputs. Output: unified object list with fused position, velocity, classification.

**Q75. Describe a cross-domain integration challenge and how you would solve it.**
Example: ADAS needs vehicle speed from Powertrain ECU, but they are on different CAN buses (ADAS on CAN FD, Powertrain on legacy CAN 2.0). Solution: central gateway bridges signal from CAN 2.0 → Ethernet SOME/IP "VehicleStateService" → ADAS subscribes. Define latency budget and gateway forwarding delay specification.
